1Welcome

ingesto copies the footage from your camera cards to as many drives as you need, then reads every copy back to make sure it is identical to the card. It is free and open source, and runs on macOS, Windows and Linux.

What it does for you

  • One card, several drives, in one pass. The card is read once and written to every destination at the same time. The copies are then checked at the same time too.
  • Several cards in a row. Load a batch of cards; they are ingested one after the other, each to every destination.
  • Folders named for you. Each card lands in a folder built from a template: counter, card name, operator, camera, date…
  • It recognises the camera from the structure of the card, and fills the camera field for you.
  • It writes what it did: an ingest report on each drive, checksum lists and MHL manifests if you want them, and a notification on your phone if you set one up.

Three promises

1 · Your card is never touched

ingesto never deletes, renames or overwrites anything on a card it copies. While a card is being ingested, any write to it is refused. The only exception is Card Tracking, an option that is off by default and writes nothing but its own small journal file (see chapter 14).

2 · "Verified" means verified

The word verified only appears when every file was read back from every destination and compared with the card (SECURE and PRO modes). A FAST copy says not verified, a SIZE CHECK copy says sizes checked, everywhere: on screen, in the report, on your phone. A run with errors is never shown as a success.

3 · It refuses to start when something is wrong

A drive that has been unplugged, two cards that would land in the same folder, a card with nothing to copy: ingesto stops before writing anything, names the problem, and tells you nothing has been copied.

2Install and first launch

Download

Get the latest version from the Releases page: github.com/noar-justedit/ingesto/releases/latest. Choose the file for your system.

macOS

  1. Open the .dmg file.
  2. Drag ingesto into your Applications folder.
  3. Launch it with a normal double-click. The app is signed and notarised by Apple: no security warning.

Windows

  1. Run the installer.
  2. The installer is not signed, so Windows SmartScreen shows a warning the first time. Click More info, then Run anyway. This is expected.

Linux

Two packages are offered: the .AppImage runs on most distributions without installing; the .deb installs on Debian and Ubuntu.

The first launch

There is no setup wizard. The window opens straight away with your mounted cards and drives in the middle. The mode is SECURE, the recommended setting. You can start working immediately; chapter 3 shows how.

Updates

When a new version is published, ingesto shows New version available at launch. Get it opens the download page, Later closes the notice.

Your computer stays awake

During an ingest, ingesto prevents the computer from going to sleep. The screen may still turn off; the copy carries on.

3Your first ingest in seven steps

The essentials on one page. Each step is detailed in the chapters that follow.

  1. Connect your card reader and your destination drives. They appear under MOUNTED VOLUMES.
  2. Drag the card onto the SOURCES zone on the left (or right-click it → Set as SOURCE).
  3. Drag one or more drives onto the DESTINATIONS zone on the right (or right-click → Set as DESTINATION).
  4. Fill in the operator, camera, picture profile and notes for the card, if you need them in the folder name or the report.
  5. Check the folder name shown in green under each destination. Change the FOLDER STRUCTURE if needed.
  6. Choose the copy mode. Keep SECURE unless you have a reason not to.
  7. Click START INGEST. Wait for the green summary ALL FILES COPIED & VERIFIED before you do anything with the card.
Before you format a card

Only format a card after a verified ingest (SECURE or PRO) to at least two drives, with a green summary. ingesto will never format a card for you.

5Loading cards

Three ways to load a card

  • Drag the card from MOUNTED VOLUMES onto the SOURCES zone. You can also drag it from the Finder or the Explorer.
  • Right-click the card → Set as SOURCE.
  • + Browse in the Sources zone, to pick a card or a folder.

When you insert a new card, ingesto offers to use it: Use as source loads it, Ignore leaves it alone.

A loaded card shows a red SRC1 badge, both in the Sources column and on its tile. The folder it will create appears in green under its name.

The card details

Each card has four fields:

  • OPERATOR: who shot it.
  • CAMERA: the camera model.
  • PICTURE PROFILE: SLOG3, CLOG, VLOG, HLG… pick one from the list or type your own.
  • NOTES: free text, recorded in the report and the notification.

These values can be used in the folder name and appear in the report.

  • Carried over: operator, camera and picture profile are kept from one card to the next. Notes describe one card and are cleared after each ingest.
  • (A) or (M): a small green (A) next to CAMERA means ingesto read the model off the card. A grey (M) means it was typed by hand.
  • The broom next to LOADED CARDS clears the four fields in one click.
  • Operator and camera accept letters and digits only, so the folder names stay clean. The picture profile is written in capitals and without spaces: s-log 3 becomes SLOG3.

Several cards

Load as many cards as you like. Each gets its own block, which you can fold with the arrow. They are ingested one after the other, each to every destination, each in its own numbered folder. Remove a card with its ×.

Write-protected card

If the card's lock switch is on, ingesto warns you before starting. You can continue (nothing is ever written to the card anyway) or remove the card.

6Choosing destinations

A destination is a drive, a RAID, a network share or a folder that will receive a full copy of each card.

Load them the same way as cards: drag onto the DESTINATIONS zone, right-click → Set as DESTINATION, or + Browse to choose a precise folder. Each one gets a green badge DST1, DST2…

  • Under each destination, ingesto lists the folders it will create, one per loaded card. Check them before starting.
  • Your destinations are remembered from one session to the next.
  • Network shares (NAS) work. In SECURE and PRO modes, ingesto really reads the copy back over the network, not from the computer's memory, so the check is genuine. It is slower; that is the price of a real check.
  • A destination cannot be the card itself, nor a folder inside it: ingesto refuses.
  • Before starting, ingesto checks that each drive has enough free space. If not, it tells you and lets you decide.
How many destinations?

Two is the usual minimum on a shoot: for example a working drive and a backup drive. ingesto writes to all of them in one pass, so a third copy costs little extra time.

7Naming the folders

Each card is copied into its own folder. Its name is built from the FOLDER STRUCTURE: a row of pieces you assemble.

The Insert menu

Click Insert to add a piece at the end of the structure. Pieces are grouped by kind:

  • THE CARD: counter, card name, camera, picture profile, operator.
  • THE DATE: year, month, day, hour, minute.
  • TYPED BY YOU: Custom text… adds a fixed text such as DAY1 or a client name.
  • SEPARATORS: underscore _ or hyphen -.

Drag the pieces to reorder them. The × on a piece removes it.

Double-click the row to type the whole structure by hand.

What each piece becomes

PieceBecomesExample
{counter}The card number (chapter 8)004
{cardname}The name of the cardA001
{operator}The operator fieldALEX
{camera}The camera fieldFX6
{pp}The picture profile fieldSLOG3
{YY} / {YYYY}Year, 2 or 4 digits26 / 2026
{MM} {DD}Month, day10 01
{HH} {MIN}Hour, minute of the ingest14 35

The default structure gives, for example: 004_A001_ALEX_FX6_261001_1435.

An empty field creates nothing, not even a stray separator. You never get 004__FX6.

Subfolders

The / button starts a subfolder. One ingest can thus build the whole tree of your project, identically on every destination.

Example: DAY1 / {camera} / {counter}_{cardname}… gives DAY1/FX6/004_A001_ALEX_261001.

Subfolder pieces are shown in blue, the card's own folder in green. A piece in italics is text you typed.

A few rules, all checked before anything is written:

  • The {counter} must be in the card's own folder, after the last /.
  • Four levels at most.
  • A subfolder level that ends up empty (a card with no camera, for example) is simply skipped. The card's own folder can never be empty: ingesto refuses instead.
  • A / typed in a field (operator, camera…) never creates a folder. Only the structure decides.

Templates

The TEMPLATES area keeps four structures, each with a name. The one in use carries a tick.

  • Click a filled template to load it.
  • Click an empty one to save the current structure there; you can give it a name.
  • Right-click a template to load, save over or delete it.
  • The icons in the header save, export and import templates, to share them with another station.

8The counter

The counter numbers your cards: 001, 002, 003… It stays at the bottom of the left column.

Auto (the normal case)

ingesto looks at what is already on your destinations and picks the next free number. Cards get consecutive numbers across sessions and days. last: 003 under the counter tells you what it found.

Manual

Type a number or use − / + to force a value. It stays locked until you click Auto, which goes back to automatic numbering.

Number of digits

The ⓘ next to COUNTER lets you choose 2, 3 or 4 digits (07, 007, 0007). It is a minimum: after 99 comes 100.

Why it matters

The counter is global to the destination, even with subfolders per day or per camera. A gap in the numbering therefore means a card is missing.

A number already used

If the number you chose already exists on a destination, ingesto refuses to start and offers to change the counter or show you the existing folder. An existing card folder is never written into.

9Choosing a copy mode

The mode decides how thoroughly each copy is checked. It is chosen at the bottom of the centre column.

ModeWhat it checksWhen to use it
FASTNothing. Copy only. Shown as not verified.Throwaway material, or an extra copy you will check elsewhere.
SIZE CHECKThat each copied file has the same size as the original. Catches an interrupted copy or a full disk, not a corrupted file. Shown as sizes checked.When time is very short and you accept the risk.
SECUREEvery file is read back from every destination and its fingerprint (xxHash) compared with the card. Detects any corruption, down to a single bit.Recommended for all rushes. The default.
PROEverything SECURE does, plus checksum lists and manifests, a choice of algorithm, and the optional double source read.When a post house, an archive or a workflow asks for checksum files.

The ⓘ next to COPY MODE explains each mode in the app.

PRO options

  • Algorithm: xxHash64, xxHash128 or MD5. Choose the one your post-production or archive asks for. MD5 is noticeably slower.
  • Double source read: after verifying the copies, ingesto reads the card a second time and checks it gives the same data. A card that answers differently is failing; those files are flagged. It makes the verification roughly twice as long.
PRO is not "more secure"

SECURE already guarantees your copies bit for bit. PRO adds files for other tools. If nobody asked you for checksum lists, SECURE is the right choice.

The checksum and manifest files PRO writes are chosen in the Settings, section WRITE CHECKSUM (chapter 14).

Why SECURE takes longer

Checking means reading every file again from each drive. ingesto deliberately bypasses the computer's memory cache so that what it reads really comes from the disk. On a slow drive or a network share, verification can take as long as the copy.

10Starting and following an ingest

The START INGEST button

Its label tells you what is missing: Load a card, then Choose a destination, then START INGEST when everything is ready.

Safety checks before anything is written

When you click Start, ingesto checks everything first. If something is wrong, a window explains what, why, and what to do. The line Nothing has been written confirms your drives and card are untouched.

Typical cases:

  • a drive or card that is no longer connected;
  • two cards that would land in the same folder (here, two cards both called A001 with no counter in the structure);
  • a counter number already used on a destination;
  • not enough free space;
  • a card with nothing to copy.

The ingest queue

During the ingest, the centre column shows the queue, and only it.

  • The ring at the top left follows the whole queue, all cards and all phases included, with the cards left, total size and time left.
  • The tiles below give the current file, files and data remaining, speed and estimated time. An Errors tile appears if anything goes wrong.
  • One block per card, with one line per destination, each with its own percentage and speed. A drive lagging behind is visible at a glance.
  • The colour says the phase: green while copying, blue while verifying, violet during the double source read, red on error.

Pause and cancel

PAUSE finishes the current file then waits; Resume continues. CANCEL stops the ingest. Everything else (cards, destinations, structure, counter, mode) is locked during the run: what you change after clicking Start cannot affect a copy already under way.

Quitting during an ingest

If you try to quit while copying, ingesto asks for confirmation. Your card is untouched either way.

11When the ingest ends

A summary window opens, with a sound. Its colour and title tell you at once whether you can trust the copies.

Everything went well

The title depends on the mode:

  • ALL FILES COPIED & VERIFIED: SECURE or PRO. The copies are proven identical.
  • ALL FILES COPIED & SIZE-CHECKED: SIZE CHECK.
  • ALL FILES COPIED: FAST. Nothing was checked.

Below: mode, number of files, size, time of each phase and average speed. Then, for each card, its folder on each drive.

  • REVEAL opens the folder in the Finder or the Explorer.
  • EJECT ejects the card (EJECT ALL for a batch).

Something went wrong

The window turns red and says plainly what happened, for example 2 FILES DID NOT SURVIVE THE COPY TO NAS_BACKUP. Under the title: Do not format this card.

The list below groups the failed files by cause. A bad copy is set aside under a name ending in .ingesto-failed, so no damaged file ever carries a valid name in your delivery folder.

Re-copy 2 failed files copies and verifies those files again, and only them. The queue shows the progress as usual.

The rule

As long as the summary is not green and verified, keep the card. If a re-copy fails again on the same drive, suspect the drive or its cable. If ingesto says the card does not give the same data twice, the card itself is failing: keep it aside.

Two notes you may see on a green summary

  • Blue, You can double-check this later. The check ran right after the copy, and part of it may have been answered by the computer's memory rather than the drive. The ingest is verified; for extra peace of mind, another day, re-plug the drive and verify the folder (chapter 13).
  • Orange, The extra card check did not really run (PRO with double source read). Your footage is fine and verified, but the second read of the card came from the computer's memory, so it did not test the card's health. Where it is possible, a button offers to run that card check again for real.

12History and reports

Ingest history

As soon as a destination is loaded, the centre column lists every card already ingested on it: number, card name, folder, number of drives, and a status badge VERIFIED or FAILED.

  • Click a line to see the details: date, number of files, size, duration, speed, mode, the time of each phase, every destination, operator, camera, profile and notes.
  • The folder icon at the end of a line shows that folder on the drive.
  • The history is read from the reports written on the drives. It survives a restart, and a drive brought from another computer arrives with its own history.
  • The eraser in the header clears the list in ingesto only. The reports on the drives are never touched, and Show it again brings the lines back.

The ingest report

After each ingest, ingesto updates a report at the root of each destination. Open the report, under the history, opens it in your browser.

  • One line per card: number, date, card, operator, camera, mode, files, size, result, the time of each phase, notes.
  • The Export PDF button turns it into a PDF to send to production or post.
  • CSV (spreadsheet) and JSON (for scripts) versions can be added in the Settings.

13Verifying a folder later

The book icon at the top right re-checks a folder that was already ingested, without copying anything.

  1. Click the book icon.
  2. Choose the card folder on the drive.
  3. ingesto reads its checksum list or MHL manifest, re-reads every file and compares.

The result shows how many files were checked, matched, corrupted or missing. ALL FILES VERIFIED means the folder is still identical to what was ingested.

When to use it

Before handing a drive to post-production, after a long journey, or months later before archiving. The folder must contain a checksum list or a manifest: keep Write Checksum on in the Settings (it is on by default).

14Settings

The gear icon at the top right opens the Settings. Each section has its own switch. Done closes the window; everything is saved straight away.

Card Tracking (off by default)

Writes a small file, .ingesto.json, on the card. When the same card comes back, ingesto knows whether it was formatted since its last ingest. This is the only option that ever writes on a card, which is why it asks for confirmation when you turn it on.

If a card comes back unformatted, ingesto tells you how many files were already ingested and how many are new:

  • COPY NEW FILES: only what was shot since. A file is skipped only if every destination already holds a verified copy of it.
  • COPY FULL CARD: everything again.
  • CANCEL: nothing.

Useful when a card goes back into the camera between two ingests.

Write Checksum (on by default)

Writes, next to the footage, files that let anyone re-check the copy later (SECURE and PRO only):

  • Checksum list: a .xxh / .md5 list, readable by ingesto and TeraCopy.
  • MHL manifest: the classic format of Silverstack, YoYotta, OffShoot (PRO with MD5 or xxHash64).
  • ASC MHL: the newer industry standard, in an ascmhl folder.

Turn on what your post-production asks for. If nobody asks, the checksum list alone is enough.

Ingest Report (on by default)

Formats: HTML to read and print, CSV for spreadsheets, JSON for scripts. Full report lists every file of each card; off, each card is a single line. VIEW opens the current report.

File Filter (off at every launch)

Copies only the file types you choose: video, audio, pictures, and other files (sidecars such as XML, THM…), each type one by one.

Copy empty folders keeps the card's empty folders.

Reorganize files on destination sorts the copied files into /VIDEO, /AUDIO, /PICTURES. Other files are then never copied.

Use with care

A filtered ingest is not a full copy of the card. That is why the filter switches itself off at every launch: you have to turn it on on purpose each time. Your choice of formats is kept.

Many cameras need their sidecar files (XML, metadata folders) to be read correctly in editing software. When in doubt, leave the filter off.

Phone Notifications (ntfy) (off by default)

Receive a notification on your phone after each card: card, operator, camera, number of files, size, mode, result per drive, time of each phase, notes. A failed card is sent as high priority.

  1. Install the free ntfy app (iPhone, Android): scan the QR code.
  2. In ingesto, enter a Topic: a long, hard-to-guess name.
  3. In the app, subscribe to that same topic.
  4. Click Send test notification and check your phone.

Leave the Server on https://ntfy.sh unless you run your own.

Privacy

On the public server, the topic name is the only thing protecting your notifications. Anyone who knows it can read them. Choose something like ingesto-studio-7x2k, not ingesto.

Post-Ingest Command and Card Handoff (off by default)

Two options for technical users who automate their workflow with scripts. Post-Ingest Command runs a command after each ingest. Card Handoff passes each card to a script of yours with a document describing what was copied and verified; Dry run tests it. Both run exactly what you type. If you do not know what to put there, leave them off.

Settings File

To set up several stations the same way. Export settings… saves a file; Import settings… applies it on another computer. The switches choose what is included: current structure, templates, copy mode, Card Tracking, checksums, report, file filter.

What is not a setting

There is no language choice: the interface is in English. Sounds and keeping the computer awake are automatic. The counter's number of digits is set from its own ⓘ (chapter 8), the kiosk PIN from the KIOSK button (chapter 15).

15Kiosk mode

A simplified, locked, full-screen view for a station shared by a whole crew: the camera operator comes, inserts the card, types their name, starts. Nobody can change the settings.

Prepare the station

  1. In the normal window, load the destinations, choose the copy mode and the folder structure. Kiosk mode uses them as they are.
  2. Click KIOSK at the top right.
  3. Choose a 4-digit PIN, then type it again to confirm.

For the person ingesting

  1. Insert the card, or click Browse a card….
  2. Type your name in Operator (required). Camera, profile and notes are optional; the camera is often filled in automatically.
  3. Click START INGEST and follow the large progress ring.
  4. Read the result, then click Next card.

The result screen speaks plainly:

  • Verified: "You can remove your card." The card is ejected automatically.
  • After FAST or SIZE CHECK: "Remove your card. Do not erase it."
  • On a problem: "Do not erase it. Call the person in charge."

If no destination was chosen, the screen says Not set up yet and asks for the person who set up the station.

Leaving kiosk mode

Click STANDARD at the top right and enter the PIN. After five wrong attempts, the pad locks for 30 seconds.

Forgotten PIN

Quit and reopen ingesto: it always starts in the normal window. The PIN is never saved; it only lasts for the session.

16Managing volumes

The MOUNTED VOLUMES area shows every card, drive and share connected, with an icon by type (card, disk, network, system disk) and the free space.

ControlUse
HIDE SYSTEMHides the computer's internal disk.
HIDE NETWORKHides network shares.
Right-click → Hide VolumeHides one particular volume. The eye icon in the header shows hidden volumes again.
Right-click → EjectEjects a card or drive without leaving ingesto. Not offered for the system disk or network shares, and refused during an ingest. If the volume was loaded, it is unloaded once the eject has succeeded.
Circular arrowRefreshes the list.

On Windows, a card's drive letter is shown in the list, for example LUMIX (D:), so two identical cards in two readers can be told apart. The folder name and the report use the bare name, LUMIX.

17Good practice on set

ingesto does the checking. These habits make the rest of the chain just as safe.

Before the shoot

  • Install ingesto and do a test ingest with a real card.
  • Prepare the folder structure and save it as a template.
  • Set up ntfy and send a test notification.
  • Prepare at least two destination drives, formatted and with enough space for the day.

For every card

  • Mode SECURE (or PRO if asked).
  • Check the folder name in green under each destination.
  • Fill in the operator, camera and notes.
  • Wait for the green summary: ALL FILES COPIED & VERIFIED.
  • Only then hand the card back to camera for formatting.

At the end of the day

  • Check the history: no red line, no gap in the numbers.
  • Export the report as PDF for production if needed.
  • Keep the two copies in two different places.

18Troubleshooting

macOS says ingesto cannot be opened, or the developer cannot be verified

Versions from 2.5.5 onwards are signed and should not show this. If you see it, you have an older version or a copy you built yourself: right-click the app in Applications → Open → Open again. Once is enough.

My card or drive does not appear

Click the refresh arrow. Check that it appears in the Finder or the Explorer. Check that HIDE SYSTEM / HIDE NETWORK are not hiding it, and click the eye icon to show hidden volumes.

The ingest refuses to start

Read the window: it names the problem and says what to do. Nothing has been copied. The most common causes are a drive that has been disconnected, two cards with the same name and no counter in the structure, or a counter number already used.

SECURE or PRO is slow

That is expected: every file is read again from every drive, from the disk itself. On a network share, verification can take as long as the copy. It is the price of a real check.

Some files failed

Do not format the card. Click Re-copy. If it fails again on the same drive, change the cable or the drive. If ingesto says the card gives different data on each read, the card is failing: keep it aside.

The counter does not give the number I expected

In Auto mode, it follows what it finds on the destinations. Look at last: under the counter. To force a number, type it; click Auto to go back.

I hid the history by mistake

Click Show it again in the history area. The reports on the drives were never touched.

The notification does not arrive

Check that the topic is exactly the same in ingesto and in the ntfy app, and use Send test notification. The computer needs an Internet connection.
